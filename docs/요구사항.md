## 1. 배경 및 현황

- BigQuery에 일간/월간 배치성으로 데이터가 유입됨 (대상 **29개 테이블**)
- 최근 1~2개월간 **배치 오류 9건** 발생 (예측 불가 데이터 오류 4건, 커뮤니케이션 오류 4건 등)
- 서비스 시작 시간 **08:30~09:00 이전**까지 모든 배치 완료가 목표
- 현재 알림 체계의 문제점:
    - 고정 시간(±5~10분) 기준이라 BW 배치(ERP 영향으로 ±20~40분 유동)에 부적합
    - 정상 배치임에도 오탐 알람 다수 발생 → 알람 피로도 증가
    - 새벽 알람은 실효성 낮음, 복구 완료 알람까지 와서 노이즈 과다
    - 데이터 적재 자체는 됐지만 품질이 깨진 케이스(중복 적재, 마스터 일부만 재적재) 탐지 불가

## 3. 실패 판정 조건 (OR 조합)

알람 조건은 그룹/테이블 단위로 설정 가능하며, 다음 조건들을 OR로 조합:

### 3.1 시간 기반 (예상 배치시간 + 버퍼)

- 예상 배치 시간 + 버퍼(맥스 타임) 내 미적재
- **BW 배치는 맥스 타임(Max Time) 방식** 적용 — 허용 최대 지연 시간 초과 시에만 알람
- 단, 버퍼 내 적재되었더라도 다음의 경우는 실패:
    - 테이블이 당일 미적재 (**월간 테이블 제외**)
    - 업데이트는 되었지만 `ROW COUNT = 0`

### 3.2 데이터 품질 기반 (전일/전월 비교)

- 전일/전월 대비 **유입 시간** 비교
- 전일/전월 대비 **Row Count** 비교
    - 트랜잭션성 테이블: 전일 적재 건수 대비 증감 (기준값 예: 25% 이상)
    - 마스터성 테이블: 전일 총량 대비 급격한 감소 (예: 50% 이상)

> 날짜 조건 적용이 어려운 마스터성 테이블은 별도 기준 정의 필요

## 4. 알람/리포트 포함 정보

- 데이터셋, 테이블명
- 배치 시간 (예상 / 실제)
- 전일 데이터 유입 시간 & Row Count
- 전일 vs 금일 Row Count 비교 및 증감량(%)
- 당일 미적재 여부
- `ROW COUNT = 0` 여부
- 전일 대비 증감량 25% 이상 여부

## 5. BO(Back Office) 설계

### 5.1 테이블 관리 (BQ 테이블 CRUD)

- 데이터셋, 테이블명
- 배치 주기: 일간 / 월간 ETL
- 배치 예상 시간 CRUD
- 버퍼(맥스 타임) 설정
- 메모(텍스트) CRUD
- 데이터 입수 체크 condition 정보

### 5.2 그룹 관리 (그룹 CRUD)

- 그룹 단위 테이블 묶음 CRUD
- **그룹 설정이 테이블 설정을 override**
- 그룹별 알람 채널 설정 가능
- 그룹/테이블 단위로 알람 조건 개별 세팅 가능

### 5.3 알람 조건 설정

- 그룹/테이블 단위로 조건 OR 조합 (위 §3 참조)
- 시간 기반 / 데이터 품질 기반 조건 각각 활성화 가능

### 5.4 글로벌 알람

- 07:45 일괄 리포트 (적재 실패/성공 모든 정보 발송)
- 글로벌 알람 대상 그룹 CRUD

### 5.5 알람 채널 CRUD

- 이메일 (수신자 관리)
- Teams Webhook 관리

### 5.6 사용자 관리

- BO 사용자 CRUD (시스템 관리자 / 일반 사용자)

### 5.7 대시보드

- 배치 성공/실패 현황
- Row Count, 증감량 추이 차트/표
- 테이블별 이력 조회
